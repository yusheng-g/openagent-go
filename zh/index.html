openagent-go

可插拔的 Go 多智能体 AI 框架

每个组件都是接口——Model、Memory、Tools、Guards、Approver、Hooks、Observer——由 7-stage 运行时组装。三种多智能体模式（子智能体委派、transfer_to 团队交接、DAG 编排），ACP v1、分层治理、WASM 插件、IM 渠道（飞书/微信/企微）。Agent 是纯配置；运行时才是执行体。

Agent 是纯配置。kernel.Runtime 是 7-stage 主循环，通过依赖注入串联独立顶层包。多智能体有三种形态：SubAgent（同步 as-tool 委派）、Team（transfer_to_* 控制权交接）、Orchestrate（LLM 规划 DAG、并行执行）。IM 渠道是进程级守护——agent 逻辑不变，渠道只是另一种传输。

核心特性

全可插拔接口

Model、Memory、Tools、Guards、Approver、Hooks、Observer——每个组件都是经 Deps 注入的接口。Agent 只持有配置；运行时负责串联。

三种多智能体模式

SubAgent（同步 as-tool 委派）、Team（transfer_to_* 控制权交接，带环检测）、Orchestrate（LLM 规划 DAG、并行批执行、auto-replan）。可组合——一个 agent 可同时在 Team 和 Plan 步骤里。

ACP v1 + IM 渠道

ACP v1 over stdio（VSCode/Zed/opencode）。另有三种 IM 传输：飞书（WebSocket 卡片、流式、审批按钮）、微信（ilinkai 长轮询、一次性回复）、企微（原生流式）。进程级守护。

7-stage 运行时

guard.in → memory.fetch → prompt.build → model.call → guard.out → tool.execute → memory.append。每个阶段发出 observe 事件；policy + execution 合并在 tool.execute 内。

分层治理

rules → safety → approval memory → human。首匹配规则、只读自动放行、多 key 全命中记忆、fail-closed 人工层。Plan 模式移除执行工具，安全探索。

WASM 插件 + 沙箱

6 种插件类型 + cron 定时任务，28 个 host 导出，wazero 运行时，Rust PDK。OS 原生沙箱（Linux bwrap / macOS Seatbelt）约束 shell、文件、网络。

架构一览

Agent 是纯配置；kernel.Runtime 是跑 7-stage 循环的薄编排层。真正的子系统——context、execution、governance、session、provider、eventbus——是独立顶层包，以接口注入，而非 kernel 的子目录。

快速开始

前置条件：Go 1.26+。

构建与运行

bash
go build -o openagent ./cmd/cli/

# Show version
./openagent -v

# ACP mode (stdio — for VSCode/Zed ACP plugins)
./openagent serve --acp

# REST mode (HTTP + SSE)
./openagent serve --port 8080

配置

json
{
  "provider": {
    "openai": {
      "api_key": "sk-...",
      "models": ["gpt-4o"]
    }
  }
}

首次运行

  1. 构建 CLI：go build -o openagent ./cmd/cli/
  2. 创建 ~/.openagent/settings.json，配置 provider（api_key + models）。
  3. 可选：在 ~/.openagent/profile/ 放 AGENTS.md（工作规则）和 SOUL.md（人设）。
  4. 运行 ./openagent serve --acp（ACP 客户端，VSCode/Zed）或 --port 8080（REST + SSE）。
  5. 开关能力：--guard on、--approver on、--sandbox（OS 级沙箱）。
  6. 把 .wasm 文件放进 ~/.openagent/plugins/——按类型自动加载。
